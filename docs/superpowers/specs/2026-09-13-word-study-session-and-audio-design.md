# 单词定额学习批次与即时语音设计

**日期：** 2026-09-13
**目标版本：** 公开版 v1.2.0
**基线版本：** v1.1.0（提交 `2f9aab8`）

## 1. 目标

把现有单词速记页从“动态筛选列表”升级为明确的定额学习批次：学习者进入页面后先设定本轮数量，开始后批次成员保持固定，标记掌握只减少本批剩余词数而不自动递补。与此同时改善本地 MP3 点击无声或延迟播放的问题，增加释义状态提示、轻量庆祝动画和本轮完成后的休息/继续选择。

公开版首页不再显示个人考试日期或倒计时。本次不修改本地个人授权版本，不改写 v1.1.0 标签或 Release。

## 2. 已确认的产品行为

### 2.1 公开版首页

- 移除“距离 10 月 17 日”“X 天”和整个考试倒计时卡片。
- 删除公开版首页对考试日期计算函数的运行时依赖；其他学习入口和公开版提示保持不变。

### 2.2 首次进入与目标数量

- 每次从首页进入单词速记页，都先显示模态弹窗“设定本次背诵目标”。
- 单词列表在点击“开背”之前不渲染，避免学习者绕过目标设定。
- 数量输入框实际默认值为 `30`。尚未编辑时数字为灰色；发生过人工输入后数字为黑色，即使重新输入 `30` 也保持黑色。
- 只接受正整数。空值、非整数或小于 `1` 时在弹窗内显示错误并保持弹窗开启。
- 输入值超过当前未掌握词数时，弹窗显示当前最多可背数量，不直接开始。
- 如果 1,911 个单词均已掌握，则显示“全部单词已掌握”，提供“查看已掌握单词”和“返回今日学习”，不显示无效数量输入。
- 左上角固定返回按钮在目标弹窗打开时仍可使用。

### 2.3 固定学习批次

- 点击“开背”时，从当前规则的候选池中一次性取得最多目标数量个单词，并保存其 ID 和固定顺序。
- 默认规则为源词表顺序。
- 批次不写入 LocalStorage；离开页面即结束本轮，再次进入必须重新设定数量。全局已掌握队列仍按现有方式持久化。
- 点击“已掌握”立即写入全局已掌握队列，但本行保留到庆祝动画结束；随后从本批剩余 ID 中移除。
- 本批剩余列表只由批次 ID 决定，不再根据全局未掌握词表重新切片，因此不会补入新词。
- 工具栏不再提供可直接改变列表的数字输入，改为显示“本轮目标 X · 剩余 Y”和“重新设定目标”按钮。“重新设定目标”打开目标弹窗，此时弹窗额外提供“取消”；点击“开背”后建立新批次，点击“取消”或按 Escape 恢复旧批次。
- 搜索仅过滤当前批次剩余单词，不从批次外引入匹配项，也不改变完成进度。

### 2.4 顺序、首字母和随机规则

- “顺序单词”“随机单词”和具体首字母属于批次生成规则。
- 当前批次建立后，点击另一个规则不会立即改变按钮选中态或单词列表，而是先打开重建确认弹窗。
- 随机规则文案为“将会重新按照随机单词排序给出 X 个单词背诵”。
- 顺序规则文案为“将会重新按照顺序排序给出 X 个单词背诵”。
- 点击“按首字母”只提示学习者选择具体字母，不重建批次；点击具体字母后才显示“将会重新按照首字母 Z 给出 X 个单词背诵”一类确认文案。
- 如果规则候选少于目标数，确认弹窗明确显示“当前最多可提供 Y 个”，确认后按实际 `Y` 个建立批次，并以 `Y` 作为本批实际目标。
- 确认后才提交新规则、生成新批次并重置本轮进度；取消后规则、按钮选中态、批次 ID、顺序、搜索内容和释义状态均保持点击前状态。
- 确认建立任何新批次后清空旧搜索条件，并将新批次所有中文释义恢复为默认显示状态。
- 当前已经是随机规则时，“重新随机”也必须经过同一个确认弹窗，然后才生成新的随机快照。

### 2.5 已掌握单词视图

- “已掌握单词”是独立的全局浏览视图，不是学习批次生成规则。
- 进入该视图不显示重建确认，不清空、不重排当前批次，也不改变本轮目标和剩余数量。
- 从该视图返回时恢复进入前的规则、批次、顺序、搜索和释义显示状态。
- 该视图继续展示全部已掌握单词，不受本轮目标限制，并保留“取消掌握”。
- 取消掌握只更新全局队列，不把该词塞入当前批次。

### 2.6 释义状态提示

- 每个学习批次单词行从左到右为：序号、单词正文、释义状态提示、语音按钮、“已掌握”按钮。
- 中文释义显示时，灰色提示为“点击可隐藏中文释义”。
- 中文释义隐藏时，灰色提示为“点击可展示中文释义”。
- 提示字号与中文释义一致，位于单词正文和语音按钮之间并居中。
- 点击正文或提示均切换释义；点击语音或掌握按钮不会切换释义。
- 窄屏时提示可换到正文下方，但必须保持居中、可点击且不遮挡语音和掌握按钮。

### 2.7 掌握庆祝动画

- 点击“已掌握”后，以该按钮为中心显示约 `800ms` 的小烟花粒子动画，不播放声音。
- 动画使用项目内 React 标记和 CSS 完成，不加入第三方动画依赖，不使用 Canvas 全屏层。
- 动画期间按钮禁用，避免重复提交；粒子层使用 `pointer-events: none`，不遮挡其他操作。
- 掌握状态立即持久化，即使动画期间离开页面也不丢失；本行在动画结束后移除。
- 如果这是本批最后一个单词，先完成烟花动画，再显示本轮完成弹窗。
- `prefers-reduced-motion: reduce` 下不播放粒子位移动画，单词立即移除并继续正常完成流程。

### 2.8 本轮完成

- 本批实际目标中的所有单词均已掌握后显示完成弹窗。
- 主标题明确说明本轮单词已经全部掌握。
- 副标题固定为“建议劳逸结合，不要急功近利哦～”。
- “先休息一下”结束本轮并返回首页“今日学习”。
- “继续背”不直接续取单词，而是重新显示“设定本次背诵目标”弹窗，由用户重新输入数量并点击“开背”。

## 3. 状态与模块边界

### 3.1 批次领域模型

新增纯领域模块管理批次快照，至少包含：

- `WordBatchRule`：`ordered`、`random` 或带具体字母的 `initial`。
- `WordStudyBatch`：本批唯一标识、请求目标、实际目标、固定单词 ID、剩余单词 ID、规则和随机种子。
- `createWordStudyBatch(...)`：从全词表、已掌握 ID、规则和目标数量建立不可递补的快照。
- `completeWordInBatch(...)`：只从剩余 ID 中移除指定单词，返回新批次。
- `filterBatchWords(...)`：仅在现有批次中执行搜索，不访问批次外候选。

`word-selection.ts` 继续负责从全词表取得规则候选和已掌握浏览结果；批次模块负责冻结候选结果。两个职责不混合。

### 3.2 页面状态机

`WordQuickStudy` 使用以下互斥页面阶段：

```text
goal → studying → completion
```

此外叠加两类临时状态：

- `pendingRuleChange`：等待确认的规则，不提前写入正式规则。
- `viewingMastered`：临时查看全局已掌握队列，保留 `studying` 批次快照。

庆祝 ID、释义可见 ID、搜索词和播放器状态作为各自独立状态，避免一个交互重置其他状态。

### 3.3 弹窗边界

- `WordGoalDialog`：目标数量、灰/黑编辑状态、输入校验和“开背”。
- `WordBatchChangeDialog`：描述待应用规则、请求目标、实际可用数量，提供“确认”“取消”。
- `WordBatchCompleteDialog`：固定副标题和“先休息一下”“继续背”。

三个弹窗都使用 `role="dialog"`、`aria-modal="true"`、明确标题关联和键盘焦点。规则确认弹窗可用 Escape 执行取消。从“重新设定目标”打开的目标弹窗允许“取消”或 Escape 回到旧批次；首次进入和完成后点击“继续背”打开的目标弹窗不能用 Escape 绕过目标设定，只能开背或返回首页。

## 4. 音频根因与改进

### 4.1 当前问题

v1.1.0 只渲染一个 `preload="none"` 的 `<audio>`。点击时才修改该元素的 `src` 并立即调用 `play()`，浏览器在用户点击后才开始读取和解析 MP3；连续点击不同单词还会让较早的播放 Promise、错误事件和较新的音源互相竞争。页面没有加载或播放状态，因此延迟和被中断都会表现为“按钮没有反应”。

音频清单和本地服务器已通过逐文件解码与 HTTP 200 验证，本次不重新生成 MP3，也不更换音色。

### 4.2 播放器设计

新增独立的 `useWordAudioPlayer`，负责：

- 建立批次后以有限并发后台读取本批本地 MP3，并缓存为 Blob URL；默认优先处理列表前部单词。
- 点击已经缓存的单词时使用 Blob URL；尚未缓存时立即使用原始本地 URL，不阻塞用户点击等待整批缓存。
- 在同一次点击处理内执行 `pause()`、设置新音源、`load()` 和 `play()`，保留浏览器用户激活语义。
- 每次点击递增播放令牌。只有最新令牌可以更新“加载中”“播放中”或错误状态，旧 Promise 和旧事件不能覆盖当前状态。
- 再次点击同一单词时从头播放；点击不同单词时立即停止上一词。
- 用 `loadstart`、`canplay`、`playing`、`ended` 和 `error` 驱动可见状态。加载期间按钮显示加载反馈；失败显示“播放失败，请再次点击”，再次点击重新尝试。
- 批次更换或组件卸载时取消后台读取、停止播放并调用 `URL.revokeObjectURL()` 释放缓存。
- 已掌握全局视图不批量预读全部历史单词，未缓存项目按需播放。

播放器不使用 Web Speech API、不访问外部接口、不改变 `/audio/words/<四位序号>.mp3` 路径。

- `App.tsx` 删除倒计时渲染和未使用的日期计算导入。
- `App.css` 删除 `.exam-countdown` 规则，并重新校准首页两个入口在桌面和窄屏下的对齐。

- 弹窗与烟花沿用项目现有蓝、绿、深灰色体系，不引入新的视觉框架。

## 6. 错误处理和边界

- 批次构造函数拒绝非整数目标、无效字母和不存在的单词 ID。
- 如果候选池在确认前因取消掌握等操作发生变化，确认时按最新候选重新计算实际数量并更新提示，不产生重复或已掌握词。
- 搜索结果为空不等于批次完成；只有剩余单词 ID 数量为零才进入完成阶段。
- 烟花定时器在卸载时清理，但掌握写入先于定时器，不会丢数据。
- 音频预读取失败不阻止背词，单个单词仍可通过原始本地 URL 重试。
- 快速连续点击只允许最后一次点击控制当前播放器状态。

## 7. 测试与发布验收

### 7.1 单元与组件测试

- 公开首页不包含考试日期和“考试倒计时”。
- 目标弹窗首次显示、列表未渲染、默认 30 为灰色、编辑后为黑色。
- 数量校验、超过候选数量以及全部掌握状态。
- 建立批次后掌握单词不递补；搜索只过滤当前批次。
- 顺序、随机、重新随机和具体首字母的确认/取消行为。
- 候选不足时按实际数量建立批次。
- 已掌握视图往返后完整恢复批次。
- 两种释义提示文案及其独立点击行为。
- 掌握立即持久化、800ms 后移除、最后一个动画结束后弹出完成提示。
- 减少动态效果下不播放位移动画。
- “继续背”回到数量弹窗；“先休息一下”调用返回首页。
- 播放器预读、命中缓存、按需回退、连续点击令牌隔离、错误提示和资源释放。
