# 公开 GitHub Release 与本地个人授权版分离设计

**日期：** 2026-09-09  
**状态：** 待用户审阅  
**目标：** 在不重写 GitHub 历史的前提下，将远程 `main` 维护为可公开免费下载、无个人授权的学习版；同时在本机保留完整的个人授权销售版，且不推送该版本后续变更。

## 1. 已确认边界

- GitHub 仓库 `yechun1993/English-lern` 保持公开；已有提交历史不进行改写或强制推送。
- 已推送的个人授权实现不含买家信息、压缩包密码、已交付的授权包或交付清单；保留其历史不会泄露个人数据。
- 个人授权销售版继续保存在当前电脑，用于之后生成每位买家的 AES-256 加密 `.7z` 包。
- 公开版不使用授权编号、授权文件、密码或交付清单；任何人可从 GitHub Release 下载。

## 2. 分支与交付结构

```text
本机，仅本地使用
└─ codex/personal-authorization-v1
   └─ 保留当前已验证的个人授权功能及后续私有改动

GitHub 公开分支
└─ main
   └─ 公开免费版源码与通用下载包

GitHub Release
└─ v1.0.0
   └─ 深大学位英语题库_公开版_v1.0.0.zip
```

本地个人授权分支不设置上游分支，也不执行推送。对外只推送 `main`，并只在 GitHub Release 上传公开版 ZIP。

## 3. 公开版行为与包内容

### 页面行为

- 移除“授权编号”“授权信息加载失败”“联系卖家”等个人授权语义。
- 以中性的公开版提示替代，例如“公开学习版 · 免费使用”。
- 保留题库、学习记录、错题复习、PWA 与局域网平板访问等现有学习功能。

### 一键启动包

公开 Release ZIP 的解压目录如下：

```text
深大学位英语题库_公开版_v1.0.0/
├─ 启动学位英语题库.cmd
├─ node.exe
├─ server.mjs
├─ 使用说明.txt
└─ site/
```

其中 `site/` 是生产构建的静态网站。包不包含源码、`node_modules`、个人授权脚本、授权文件、买家数据、卖家账本或密码。使用者在 Windows 上解压后双击启动器即可打开网站；同一可信 Wi-Fi 下的平板可访问启动窗口显示的局域网地址。

## 4. 构建与发布流程

1. 从当前已验证提交创建本地 `codex/personal-authorization-v1` 分支，作为个人授权版基线。
2. 在 `main` 将授权展示替换为公开版提示，新增仅打出通用运行包的公开版打包器，并保留现有个人授权工具只在本地分支中维护。
3. 对公开版运行单元测试、内容校验、代码规范、生产构建、授权包/公开包测试以及 Edge 桌面与手机端到端测试。
4. 构建 `深大学位英语题库_公开版_v1.0.0.zip`，检查解压后不含私有文件、启动器能够启动并可访问题库。
5. 将公开版提交推送到 GitHub `main`，创建 `v1.0.0` GitHub Release，上传 ZIP，并写明 Windows 使用方式、局域网使用边界与学习记录仅存浏览器本地的限制。

## 5. 异常处理与验收

- 如果发布电脑缺少 7-Zip，公开版生成器应给出明确提示并停止，不产生不完整 ZIP。
- 如同名 Release ZIP 已存在，应停止并提示先更改版本号，避免覆盖历史文件。
- 生成失败后必须清理临时打包目录。
- GitHub Release 创建或上传失败时，不修改本地个人授权分支，也不强制推送远程历史。

验收条件：

1. 本机可切换回个人授权版并生成已有格式的授权 `.7z` 包。
2. GitHub `main` 的当前页面与下载包均无个人授权编号和卖家联系提示。
3. `v1.0.0` Release 可公开下载，ZIP 解压后能双击启动。
4. 公开包不含源码、依赖目录、授权文件、账本或密码。
